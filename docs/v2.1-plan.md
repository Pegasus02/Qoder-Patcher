# v2.1 Modification and Verification Plan

## Objective

Route configured Qoder CN BYOK models directly to an arbitrary OpenAI-compatible service, including CPA, Ollama, vLLM, or a self-hosted gateway, without sending the inference request to Qoder's cloud gateway.

## Implementation stages

1. Confirm the BYOK serialization path and the hidden external-provider transport.
2. Inject a direct-target builder that combines local non-secret model metadata with Qoder's in-memory BYOK API Key.
3. Normalize the upstream base URL and prevent fallback when a configured model is incomplete.
4. Extend DryRun checks to cover the new route anchor, injected helper, and generated JavaScript syntax.
5. Support a transactional v2-to-v2.1 upgrade from a verified original Runtime backup.
6. Apply the patch only after Qoder is closed, then perform an end-to-end CPA request.

## Acceptance criteria

- `app.asar` remains byte-for-byte unchanged.
- Runtime and app hashes match the supported Qoder CN 0.1.2 / Runtime 1.1.31 baseline.
- DryRun finds every anchor exactly once and `node --check` accepts the generated Runtime.
- The configured model produces an `[ExternalProviderRequest]` log with `provider=qoder-cn-patcher`.
- The same request does not produce a `[QoderInferRequest]` cloud-gateway send.
- CPA receives `POST /v1/chat/completions` with the selected model.
- Apply and upgrade failures restore the previous Runtime; Restore verifies the original backup hash.

## Deferred items

- Automatic adaptation for non-OpenAI wire protocols.
- Support for Qoder builds with different Runtime hashes or changed minified anchors.
- Declaring v2.1 stable before the installation-level CPA test passes.
